# フレンド確認と合流のUI仕様草案

## 利用目的

ゲーム内に古い居場所が表示され、会いたいフレンドのいるインスタンスに合流できないことがある。アプリを開いた時点で取得できる情報を確認し、行き先を特定できればゲーム内で招待を受け取って合流できるようにする。表示する時刻はアプリが取得に成功した時刻を表す。

主な使い方は「お気に入りから人を探す」、次いで「フレンドの集まっている場所から選ぶ」。VRCXのような多機能な画面、常駐して情報を集める動作、フレンドの行動履歴を残す機能には抵抗感がある。初版は、利用者が今知りたい情報と合流操作に絞る方針とする。

## ここまでに決めたこと

| 場面 | 画面の振る舞い |
| --- | --- |
| 会いたい人を探す | ホームでは現在のVRChatアカウントのゲーム内お気に入りを使う。「フレンド」タブで「全フレンド」またはゲーム内の好きなグループを選べる。前回選んだ表示範囲をアカウントごとに開き、オンラインの人を先頭に、オフラインの人も同じ一覧に表示する。 |
| ステータスメッセージを読む | 全フレンド・お気に入り・検索結果では、各行の同じ列に状態を示す丸と本人のステータステキストを表示する。テキストが空または空白だけなら標準の状態名を使う。長文は一覧で省略し、詳細で全文を読める。[一覧の実装](../../src/screens/friendScreen.tsx) |
| 名前で探す | 検索語を入力すると、使用中のアカウントの全フレンドを対象に名前で検索する。お気に入り未登録の人やオフラインの人も対象。検索語を消すと、検索前に選んでいた表示範囲に戻る。[検索結果の画面例](../../design/friend-search.png) |
| 行き先から探す | インスタンス一覧は、そのアカウントの全フレンドを対象にするのが標準。選択中のお気に入りグループでも絞り込める。標準表示でもお気に入りの人には星を付ける。 |
| お気に入りで場所を絞る | 選択中のグループのメンバーがいるインスタンスを表示する。その場所にいるフレンドはグループ外の人も含めて表示し、誰と合流することになるか分かるようにする。 |
| アカウントを切り替える・追加する | ホーム右上の現在のアカウント名を押すと、登録済みアカウントの一覧と「アカウントを追加」が開く。切り替え先では、そのアカウントで選んでいたフレンドの表示範囲を開く。 |
| 手動でログアウトする | 設定画面の「アカウント」欄に「ログアウト」を置く。実行すると対象アカウントをこの端末の切り替え一覧から外す。再び使うときは「アカウントを追加」からログインする。他のアカウントの登録は保持する。 |
| ログアウト後に登録が残る | 残りが1件ならそのアカウント、2件以上なら残った中で最後に使用したアカウントに自動で切り替え、そのアカウントのフレンド一覧を開く。認証期限切れなら対象アカウントの再ログイン、通信失敗なら再試行を表示する。 |
| アプリを開き直す | フレンドの状態・居場所・一覧は起動をまたいで保存しない。前回の表示範囲とお気に入りグループの選択を覚え、一覧を新しく取得する。現行版の保存済み一覧も新ホームには表示しない。 |
| 合流する | 指定したインスタンスへの招待を自分で受け取る既存機能を継続する。合流はその招待をゲーム内で開いて行う。 |

右上のアカウント欄とフレンドの一覧・詳細にはユーザーアイコンを表示する。アイコンを取得できない場合はプロフィール画像やアバター画像を順に試し、画像がなければ名前の先頭の文字を表示する。

フレンド一覧は、全員・選択グループ・検索結果ごとに「6人中 4人がオンライン」の形式で表示する。オンライン人数はフレンド一覧APIがオンラインとして返したユーザーを数える。取得中や失敗後は手元にある件数を暫定値とし、まだ数えられない場合は集計中または未確認と表示する。[フレンド一覧API](https://vrchat.community/reference/get-friends)・[全フレンドの画面例](../../design/all-friends.png)

## フレンドのステータス表示

一覧では丸の色で状態を示し、ラベルには本人のメッセージを優先する。詳細では標準の状態名とメッセージの全文を表示する。詳細取得で一覧のオンライン判定を更新するときは接続状態（state）を使う。Web利用中は現在地が offline になることがある。[フレンド一覧API](https://vrchat.community/reference/get-friends)・[VRChatのステータスと色](https://wiki.vrchat.com/wiki/Social)・[ステータス表示](../../src/components/ui/socialDetail.tsx)

| 取得したステータス | 表示ラベル（案） | 色 |
| --- | --- | --- |
| `join me` | 合流歓迎 | 青 |
| `active` | オンライン | 緑 |
| `ask me` | 先に聞いて | オレンジ |
| `busy` | 取り込み中 | 赤 |
| `offline` | オフライン | グレー |

状態を特定できない場合のラベルは「状態不明」。通信失敗時に以前の一覧を表示する場合は、最後に取得できた状態と最終確認時刻を一緒に表示する。自己招待の可否は、詳細を開いて居場所を特定できたかで決める。

## インスタンス一覧の分類

インスタンス一覧では「絞り込み」を初期表示で折りたたみ、見出しに現在の対象・お気に入りグループ名・適用中の種別を表示する。条件を変えるときは見出しを開く。閉じても選択は保持し、並び順は一覧上部でいつでも変更できる。

「探す対象」は「全フレンド」「お気に入りから」「所属グループ」から選ぶ。「お気に入りから」を選ぶと、その下にVRChatで設定したグループ名が並ぶ。初期表示は「全フレンド」かつインスタンス種別「すべて」。[お気に入りから探す画面例](../../design/instances-favorites.png)

| 操作 | 選択肢 | 表示条件 |
| --- | --- | --- |
| 探す対象（フレンドから） | 全フレンド／お気に入りから | 対象のフレンドが1人以上いる場所を表示する。 |
| 探す対象（グループから） | 所属グループ | 使用中のアカウントに取得が許された所属グループの開催中の場所を、フレンドの有無を問わず表示する。 |
| フレンドから探すときのインスタンス種別 | すべて／グループ主催／グループ以外 | 「グループ主催」はVRChatグループが開いた場所、「グループ以外」はそれ以外と判明した場所を表示する。 |

一覧の並び順は「フレンドが多い順」を初期値とし、「取得順」にも切り替えられる。場所ごとに確認できた全フレンドを数え、お気に入りで絞ったときもグループ外のフレンドを含める。人数が同じ場所は元の取得順を保つ。

フレンドから探すときは、両方の条件を満たす場所を表示する。たとえば「よく遊ぶ人」と「グループ主催」を選ぶと、そのお気に入りメンバーがいるグループインスタンスだけが残る。各場所には、そこにいる他のフレンドも表示する。該当が0件なら、選択条件を保ったまま空の一覧を表示する。

分類にはAPIのインスタンス種別を使う。`type` が `group` の場合、`groupAccessType` の `public`・`plus`・`members` はいずれも「グループ主催」に含める。公開範囲は一覧と詳細に、取得できた主催グループ名は詳細に表示する。種別が未確認の場所は「すべて」に含め、ワールド名やフレンド名から主催者を推測しない。[インスタンスAPI](https://vrchat.community/reference/get-instance)・[種別と公開範囲](https://vrchat.community/instances)

「所属グループ」を選ぶと、そのアカウントのグループインスタンス一覧を表示する。主催種別の切り替えはこの表示では省く。カードに主催グループ名を添え、同じワールドでも別インスタンスは別の場所として扱う。参加中のフレンドを確認できれば名前を表示し、誰も確認されなければ「フレンド 0人」、フレンド情報の取得に失敗した場合は「フレンド未確認」とする。全体の人数・定員、入場待ち、選択した場所への自己招待は他のインスタンスと共通。[所属グループの画面例](../../design/member-instances.png)・[所属グループのインスタンスAPI](https://vrchat.community/reference/get-user-group-instances)・[現行の取得処理](../../src-tauri/src/commands.rs)

各カードにはワールドのサムネイルを表示する。フレンドの現在地からワールドIDが判明した時点で、ワールド名と画像の取得を開始する。インスタンスに個別の表示名がある場合は番号の隣に添える。[ワールド取得API](https://vrchat.community/reference/get-world)・[一覧の実装](../../src/screens/friendScreen.tsx)

各カードのワールド名の横に「全体 18／20人」の形式で、そのインスタンスの現在人数（`userCount`）と定員（`capacity`）を表示する。インスタンス詳細でも同じ表記を使う。お気に入りや主催種別で絞っても分子はインスタンス全員の人数とし、カード下段に各フレンドの小さなアイコンと名前を並べる。インスタンス詳細でも自己招待ボタンの上に「この場所にいるフレンド」を表示し、カードと同じメンバー・アイコン・お気に入りの星を表示する。詳細欄のフレンド名を選ぶと同じパネルでその人の詳細を開き、「インスタンス詳細に戻る」で元の場所に戻る。相手の移動後も元のインスタンスを保持する。複数人いる場合はアイコンと名前を組にして折り返す。取得できていない値は「—」で示し、取得済みの0人と区別する。[一覧の画面例](../../design/instances.png)・[現行の人数表示](../../src/components/ui/dialogs/instanceDetail.tsx)・[インスタンスAPI](https://vrchat.community/reference/get-instance)

インスタンス一覧・詳細ともに、待機列が有効（`queueEnabled`）で、取得した待機人数（`queueSize`）が1人以上なら、人数・定員のそばに「3人待ち」の形式で表示する。待機列が無効、0人、または待機情報が未取得の場合はバッジを表示しない。満員でも人数・定員だけから待機人数を推測しない。[待機列の画面例](../../design/instance-groups.png)・[インスタンスAPI](https://vrchat.community/reference/get-instance)

画面例では「全フレンド」と「グループ主催」を選択し、右側に主催グループ名を表示している。[画面プレビュー](../../design/instance-groups.png)・[AltPenデザイン](../../design/friend-home.pen)

## 登録アカウントがないときのログイン

初回・アカウント追加・再ログインと二要素認証のフォームでは、タイトルと入力欄の間に、認証情報の端末保存と送信先、非公式アプリの利用、商標についての旧版の注意文を3段落で常時表示する。[注意文の原文](../../src/locales/ja.json)・[現行フォーム](../../src/components/ui/sessionForm.tsx)

登録アカウントが0件なら、起動した画面に「ユーザー名またはメールアドレス」と「パスワード」の入力欄を直接表示する。最後のアカウントから手動ログアウトして0件になった場合もこの画面に戻る。[初回ログインの画面例](../../design/first-login.png)

「ログイン」を押して二要素認証が要求された場合に限り、指定された方法のコード入力へ進む。認証アプリなら「認証アプリに表示された確認コード」、メールなら「VRChatから届いたメールの確認コード」と案内する。コードが誤っている場合は同じ画面で入力し直せる。[認証アプリの画面例](../../design/login-totp.png)・[メール認証の画面例](../../design/login-email.png)・[現行のログイン画面](../../src/components/ui/dialogs/login.tsx)

認証が完了したら、そのアカウントのお気に入りホームを開く。グループは以下の初期選択ルールに従う。

## 使用中に別のアカウントを追加する

ホーム右上の「アカウントを追加」からログインする。必要な場合は初回ログインと同じ二要素認証を行う。[追加フォームの画面例](../../design/add-account.png)

- **成功時**は必要な認証をすべて終えて追加先のアカウントを確認してから、登録と切り替えを行う。追加先のホームで、そのアカウントのお気に入りを取得する。[切り替え直後の画面例](../../design/added-account-home.png)
- **中断時**はコード入力の途中も含め、元のアカウントと画面に戻る。グループ選択・検索語・選択中の詳細は追加を始める前の状態を保つ。
- **認証や通信に失敗した場合**は元のアカウントを使用中のままにし、追加フォームで再試行またはキャンセルできる。

## 認証期限切れからの再ログイン

期限切れのアカウントで「再ログイン」を選ぶと、対象の表示名を固定表示する。保存済みのログインIDを利用できるときはIDも固定表示し、入力するのはパスワードと、要求された場合の確認コード。別のアカウントを使うときはアカウント選択に戻る。[再ログイン画面例](../../design/reauth.png)

認証には、初回ログイン・追加に成功したときのユーザー名またはメールアドレスを対象アカウントに紐付けて使う。パスワードや確認コードは保存しない。必要な認証が完了したら、返されたユーザーIDが対象のユーザーIDと一致したときだけ、そのアカウントのセッションを更新して元のお気に入りグループに戻る。[現行のログイン処理](../../src-tauri/src/commands.rs)・[認証API](https://vrchat.community/reference/get-current-user)

旧版の登録などで保存済みのログインIDを利用できない場合は、再ログインの回数にかかわらず、再ログインの対象を固定し、そのアカウントのユーザー名またはメールアドレスを入力してもらう。必要な二要素認証まで完了し、返されたVRChatユーザーIDが登録済みの対象と一致したときだけ、入力したログインIDをそのアカウントに保存する。失敗・中断・別アカウントとの不一致の場合は元の登録を保持し、再試行できる。[ログインIDの入力例](../../design/reauth-missing-login-id.png)・[保存済みIDを利用できる場合の画面例](../../design/reauth.png)

## お気に入りグループの初期選択

お気に入りは閲覧専用とし、登録・解除・グループ間の移動はVRChat側で行う。アプリではゲーム内のグループを切り替えて閲覧でき、未登録の人も全フレンド検索で探せる。星印は登録済みであることを示す。

フレンドのお気に入りグループは、通常は枠数が変わらない前提で扱う。API資料ではフレンド枠の内部名に `group_0`、`group_1` などが使われる。グループ選択はアカウントごとにこの内部名で記憶し、画面では使用中のアカウントを所有者、friendを種別としてグループ一覧を取得し、各枠の `displayName` を表示する。フレンド一覧とインスタンスの絞り込みで同じ表示名を使う。表示名が空、または `group_0` などその枠の内部名だけの場合、ログイン時の `friendGroupNames` に同じ番号の表示名があれば使う。表示名がどちらにもない標準枠は、ゲーム内と同じ `Group 1`、`Group 2`、…と表示する。番号は内部名の末尾から決め、表示言語や一覧の取得順には依存しない。[お気に入りグループ一覧](https://vrchat.community/reference/get-favorite-groups)・[コミュニティのAPI資料](https://vrchat.community/reference/get-favorite-group)

- そのアカウントの初回利用時は、取得したフレンド枠のうち、末尾の番号が最も小さい枠を自動で開く。通常は `group_0` を開く。登録人数が0人でも同じ枠を表示する。
- ホームで「全フレンド」を選んだ場合は次回も全員を表示する。インスタンス絞り込み用のお気に入り枠は別に覚える。
- お気に入り表示の場合、次回以降は前回選んだ枠を開く。グループ一覧を正常に取得でき、保存した枠が存在しないと確認できた場合も、初回と同じ規則で選ぶ。
- グループ一覧の取得に失敗した場合は、前回の選択を保持し、その場で再試行できるようにする。

選択したお気に入りグループの取得に成功して登録が0人なら、選択を保ち「このグループにはまだフレンドがいません」と表示する。上部のグループ切り替えと全フレンド検索はそのまま使え、検索語を消すと元の空のグループに戻る。[空のグループの画面例](../../design/favorite-group-empty.png)

## 全フレンド検索の取得状況

検索欄の直下を取得状況の表示位置とする。検索語を変えても、その時点で取得できているフレンドから名前が一致する人を表示する。オンライン・オフラインの両方を最後まで取得した時点で検索結果を確定する。[現行のフレンド取得処理](../../src/screens/friendScreen.tsx)

| 取得状況 | 表示と操作 |
| --- | --- |
| 取得中 | 小さなスピナーと「フレンド一覧を取得中…」を表示し続ける。一致した人は到着順に検索結果へ反映し、表示された人の詳細を開ける。まだ一致する人がいない間も取得中の表示を保つ。[画面例](../../design/friend-search-loading.png) |
| 途中で通信に失敗 | 取得中の表示を「一部のフレンドを取得できませんでした」と「再試行」に切り替える。検索語と表示済みの結果を保つ。再試行中は同じ位置に取得中の表示を戻す。[画面例](../../design/friend-search-interrupted.png) |
| 全件取得が完了 | 取得中の表示を消す。この時点で一致する人が0人の場合に限り、「『検索語』に一致するフレンドはいません」と表示する。[0件の画面例](../../design/friend-search-empty.png) |

## 更新と復旧

初回取得と更新失敗を次のように区別する。初回は、現在の起動中にそのアカウントの対象一覧を一度も取得できていない状態を指す。

| 状況 | 表示と操作 |
| --- | --- |
| 初回取得中／成功 | 取得中であることを表示し、成功したら一覧と最終確認時刻を表示する。空のグループの案内は、取得に成功して登録が0人と確認できた場合に限る。 |
| 初回取得に失敗 | 「お気に入りを取得できませんでした」と「再試行」を表示する。 |
| 表示中の一覧の更新に失敗 | 同じアカウント・同じ表示対象の直前の一覧を残す。「更新に失敗しました。20:42時点の情報です」のように示し、その場で再試行できる。一部だけ取得できた場合も一覧の最終確認時刻は進めない。未取得の人をオフライン扱いにしない。 |
| 認証期限切れ | 対象アカウント名と「再ログイン」を表示する。登録とグループ選択を保持し、再認証できたら元のグループを再取得する。他のアカウントにも切り替えられる。 |
| アカウント切り替え中 | 表示、取得結果、最終確認時刻をアカウント単位で扱う。前のアカウントの応答が遅れて届いても、切り替え先には反映しない。手動切り替えで切り替え先の認証に失敗したときは、ログイン中の元のアカウントで操作を続けられる。 |

アプリに戻ったときのフレンド・インスタンス一覧の更新は手動とする。前回の取得からどれだけ時間が経っていても、ウィンドウを再表示しただけでは通信せず、一覧と最終確認時刻を保持する。「更新」を押して取得に成功した時点で一覧と時刻を更新する。

起動時・アカウント切り替え時には対象アカウントの一覧を取得する。フレンド詳細を開いたときには、その人の現在地を取得する。フレンドの状態変化や訪問先の履歴を蓄積せず、バックグラウンドでの定期取得は初版の対象外とする。

フレンド詳細で現在地を取得できたら、同じアカウントのその人の行にも反映する。お気に入り一覧・全フレンド検索のどちらで見ても同じ居場所を表示する。取得結果が非公開・移動中の場合もその状態に更新する。他の人の行と一覧全体の最終確認時刻は保持し、詳細の現在地には個別の取得時刻を表示する。通信失敗時はその人の居場所と確認時刻を更新せず、詳細から再取得できる。古い一覧取得の応答が遅れて届いても、より新しく確認した居場所を巻き戻さない。[一覧を20:42、選んだ人の現在地を20:50に確認した画面例](../../design/friend-location-refreshed.png)

## フレンドのプロフィール

フレンドを選ぶと、右パネルにステータスと現在地を表示する。招待先を特定できたときは、同じパネルから自分に招待を送れる。[通常のフレンド詳細](../../design/friend-home.png)

「Webでプロフィールを開く」はフレンド詳細・プロフィールのどちらからでも、その人のVRChat公式プロフィールを既定のブラウザで開く。[インスタンス経由の画面例](../../design/instance-friend-detail.png)

右上の「プロフィールを見る」を押すと、右パネルで公開プロフィールAPIから取得した本人の自己紹介とプロフィールリンクを読める。取得中・取得失敗を表示し、失敗時はこの欄で再試行できる。[公開プロフィールAPI](https://vrchat.community/reference/get-public-profile)リンクを選ぶとブラウザで開く。「フレンド詳細に戻る」で同じ人の現在地と合流操作に戻る。切り替えの前後で、左側の一覧・検索語・選択中のフレンドを保つ。[プロフィールの画面例](../../design/friend-profile.png)・[現行のプロフィール項目](../../src/components/ui/dialogs/friendDetail.tsx)

フレンド本人の利用プラットフォーム（PC・Androidなど）は、お気に入り一覧・全フレンド検索・フレンド詳細・プロフィールのいずれにも表示しない。

## 自分宛ての招待

現行の自己招待処理にはワールドIDとインスタンスIDが必要。フレンド詳細を入口にする場合も、この2つで特定したインスタンスを使う。[既存のインスタンス詳細](../../src/components/ui/dialogs/instanceDetail.tsx)・[自己招待コマンド](../../src-tauri/src/commands.rs)

| 入口 | 操作案 |
| --- | --- |
| フレンド詳細 | 詳細を開いたときに居場所を再取得する。インスタンスを特定できたら、現在地にワールド名・種別・全体の人数／定員を表示し、その下に自己招待ボタンを置く。入場待ちが1人以上なら同じ欄に「3人待ち」の形式で表示する。未取得の値と待機列の表示条件はインスタンス一覧と共通。[画面例](../../design/friend-queue.png) |
| インスタンス詳細 | 利用者が選んだインスタンスから「自分に招待を送る」を実行する。フレンドが移動しても別の場所へ自動で宛先を変えない。 |

インスタンス詳細では「自分に招待を送る」の下に小さく「ブラウザで開く」リンクを置く。選択中のインスタンスを外部ブラウザで開き、自己招待の送信は行わない。[画面例](../../design/instances.png)

フレンド詳細からの自己招待では、画面に表示したインスタンスを宛先とする。居場所の取得後にフレンドが移動していても、送信時の再照会や確認ダイアログを挟まず、表示したワールドIDとインスタンスIDで自己招待を試みる。

詳細を開いた時点で居場所が非公開・移動中なら、その状態を表示する。取得に失敗した場合は「現在地を再取得」を表示する。いずれも今回の招待先は未確定のため、自己招待ボタンは表示しない。

招待を受け取るアカウント名を「自分に招待を送る」ボタンのすぐ上に表示する。成功時には「自分に招待を送りました」と表示する。

フレンド詳細・インスタンス詳細ともに、送信後に応答が途切れて結果を確かめられない場合は「送信結果を確認できませんでした」とだけ伝える。通信が回復しても自動では再送しない。メッセージの横に控えめな「再送」ボタンを置き、利用者が押したときだけ、元のアカウントから同じワールドID・インスタンスIDへ1回送る。送信中は連続して押せないようにする。[送信結果が不明なときの画面例](../../design/self-invite-unknown.png)

## 起動時のアプリアップデート通知

設定で起動時の自動確認が有効なとき、更新が見つかったらホーム上部に「アップデートがあります」を表示する。フレンドの確認や自己招待はそのまま続けられる。[ホームの通知例](../../design/update-notice.png)

通知を押すと、対象のバージョン、変更内容、適用時に再起動する旨を表示する。「更新して再起動」を押したときにダウンロードと適用を開始し、成功後に再起動する。「後で」を押すと元の画面に戻り、通知からもう一度開ける。設定画面の手動確認からも更新内容を開ける。[更新内容の画面例](../../design/update-details.png)・[現行の更新処理](../../src/App.tsx)・[手動確認](../../src/screens/settingsScreen.tsx)

## 設定画面の配置

左下の「設定」から開く。ホームと共通のナビゲーションと右上のアカウントメニューを残し、本文は1列にする。ラベルを左、選択値や操作を右に置く。[設定画面の配置案](../../design/settings-overview.png)・[現行の設定画面](../../src/screens/settingsScreen.tsx)

| 上からの順序 | 項目 |
| --- | --- |
| 表示 | 表示言語、ライト／ダーク。変更をその場で反映する。 |
| アカウント | 使用中の表示名と、そのアカウントの「ログアウト」。切り替えと追加は右上のメニューから行う。 |
| アプリの更新 | 起動時の更新確認、ベータ版の更新を受け取る設定、現在のバージョン、「今すぐ確認」。更新が見つかったら変更内容を開く。 |
| 詳細設定 | 「フレンド一覧の取得設定」を展開し、「1回の通信で取得するフレンド数」を変更できる。初期値は50人で、1〜100人の整数を指定する。[展開時の画面例](../../design/settings-friend-count.png) |
| このアプリについて | サードパーティライセンスを設定のサブ画面で開く。 |

ライセンス画面は共通のヘッダーとナビゲーションを使う。npm・Cargoを件数付きで切り替え、パッケージ名で絞り込める。行には名前・バージョン・ライセンス種別を表示し、展開すると同梱の本文を改行を保ったまま読める。「設定に戻る」は一覧をスクロールしても上部に残る。読込失敗時は再試行できる。[一覧の画面例](../../design/settings-licenses.png)・[本文の画面例](../../design/settings-license-text.png)・[実装](../../src/screens/licensesScreen.tsx)

取得件数はアプリ共通の設定として保存し、次にフレンド一覧の取得を始めるときに適用する。取得中の一覧は開始時の件数で最後まで読み込む。件数を小さくしても検索対象は全フレンドのままとする。空欄・小数・範囲外の値を確定しようとした場合は、入力欄の下に「1〜100の整数を入力してください」と表示し、直前の有効な設定を保つ。[現行の取得処理](../../src/screens/friendScreen.tsx)・[設定値の保存先](../../src/libs/userDataStore.ts)

## アプリ内の通知と履歴

自己招待などの操作結果を通知し、使用中のアカウントの「最近の通知」を右上のベルから開ける。エラーは診断用ログにも記録する。[通知履歴と表示](../../src/App.tsx)・[招待の結果表示](../../src/components/ui/socialDetail.tsx)

「最近の通知」には、自己招待の送信結果やフレンド一覧の更新失敗など、使用中のアカウントの操作結果を時刻付きで表示する。通知を閉じた後も、同じ起動中なら履歴を読み返せる。履歴はアカウントごとにメモリ上で保持し、アプリの終了時に破棄する。次回起動時は空の一覧から始める。フレンドの状態変化や訪問先は収集しない。

終了後の不具合調査には、警告やエラーをファイルに記録する既存の診断用ログを使う。[警告・エラーの記録](../../src/components/toast.tsx)・[ログファイルの出力設定](../../src-tauri/src/lib.rs)
